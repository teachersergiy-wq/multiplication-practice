# Експлуатація: Supabase Free і щоденні дії власника

Документ для власника проєкту. Те, що перевірено на живій базі, позначено **VERIFIED**; те, що взято з документації Supabase й потребує звіряння перед покладанням, — **ЗВІРИТИ**.

## 1. Обмеження безкоштовного плану
- **Резервні копії (ЗВІРИТИ):** на Free автоматичних резервних копій немає. Дані учнів і тестів відновити буде нікому, тож копію робимо самі (розділ 2).
- **Пауза (ЗВІРИТИ):** проєкт Free ставиться на паузу після періоду без активності (за документацією Supabase — близько тижня). Під час паузи застосунок не працює; відновлення — кнопка Restore project у Dashboard. Перед початком навчального тижня відкрий застосунок і переконайся, що вхід працює.
- **Пошта (ЗВІРИТИ):** вбудована пошта Supabase обмежена кількома листами на годину. Проєкт від листів не залежить: вчителів створює власник, учні входять за логіном і паролем.
- **Free-квоти** (місце в базі, виклики функцій, трафік) дивись у Dashboard → Settings → Usage. Плани без фінансових витрат (рішення власника): якщо квота наближається до межі, спершу зменшуємо обсяг даних, а не переходимо на платний план.

## 2. Резервна копія вручну
1. Dashboard → Table Editor → відкрий таблицю → Export to CSV для `profiles`, `classes`, `class_students`, `assessment_templates`, `assessment_questions`, `assessment_assignments`, `assessment_attempts`, `assessment_responses`. Шаблони й питання важливіші за спроби.
2. Ключі відповідей лежать у схемі `private.assessment_answer_keys` і через Table Editor можуть не експортуватися. Не копіюй їх у месенджери й пошту. Якщо потрібна копія ключів, попроси координатора підготувати експорт через SQL і зберігай файл лише в приватному місці.
3. Робити копію раз на місяць і перед кожною міграцією, що змінює дані.
4. Файли міграцій лежать у репозиторії `supabase/migrations/`: схему можна відтворити з них.

## 3. Як додати вчителя без SQL у коді
Зараз вчитель потрапляє в систему так (D7, лише за запрошенням):
1. Власник створює користувача в Dashboard → Authentication → Users → Add user (e-mail + пароль, Auto Confirm User).
2. Адресу e-mail треба додати до приватного списку дозволених (`private.allowed_teachers`). Поки немає інтерфейсу, це робиться одним рядком SQL у SQL Editor (попроси координатора підготувати рядок для конкретної адреси; адресу в чат повідомляє власник).
3. Вчитель входить у застосунок: функція `provision-teacher` створює йому профіль, лише якщо адреса є в списку.
4. Окреме завдання «додавання вчителів без SQL» стоїть у беклогу.

## 4. Секрети й ключі
- Секрети Edge-функцій (`ALLOWED_ORIGINS`, `STUDENT_EMAIL_DOMAIN`) задає власник у Dashboard → Edge Functions → Secrets. Значення не пересилаємо в чат, код чи issue.
- У збірці GitHub Pages використовуються лише публічні змінні (`VITE_SUPABASE_URL`, публічний ключ, `VITE_STUDENT_EMAIL_DOMAIN`). Сервісний ключ (`service_role`) ніколи не потрапляє у фронтенд.
- **Ротація ключів:** якщо `service_role` або пароль бази могли потрапити в чат, репозиторій чи скріншот, зміни їх у Dashboard → Settings → API / Database і перезапусти функції. Після зміни публічного ключа онови його в налаштуваннях збірки GitHub Pages і запусти workflow Pages.
- Публічну реєстрацію вимкнено (VERIFIED 2026-10-25: sign up, anonymous, manual linking вимкнені; Email увімкнено, Phone вимкнено). Перевіряй цей екран після кожної зміни налаштувань Auth.

## 5. Міграції
- Агенти не застосовують міграції до production. Власник виконує файл у **новому порожньому** вікні SQL Editor (весь файл обгорнуто в `begin; … commit;`) і повідомляє координатора; координатор перевіряє результат запитом.
- Не вставляй старий великий скрипт у те саме вікно: він може повернути старі версії функцій.
- Після міграції, що змінює Edge-функції, координатор перерозгортає їх і звіряє список функцій.

## 6. Перевірки перед навчальним тижнем
1. Застосунок відкривається з телефона; вхід учня й вчителя працює.
2. Проєкт не на паузі (Dashboard показує Active).
3. Усі активні тести призначено потрібним класам; дата й час спроб відповідають розкладу.
4. Свіжа резервна копія (розділ 2).

## 7. Що не перевірено
- Фактичні ліміти й терміни паузи Free на цьому проєкті (ЗВІРИТИ в Dashboard і документації).
- Експорт ключів відповідей і відновлення з копії не відпрацьовані.
- Повний потік на телефоні (360×640, 390×844) не пройдено.

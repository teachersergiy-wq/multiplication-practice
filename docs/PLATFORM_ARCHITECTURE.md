# Навчальна студія — платформа тестів

**Статус: PARTIAL.** Є робоча оболонка бібліотеки та локальний конструктор чернеток. Базова схема вже застосована в окремій базі. Вхід, синхронізація, публікація тесту й запуск для учня ще не реалізовані.

## Напрямок продукту

Застосунок має підтримувати тести з різних предметів і для різних класів. Множення — перший готовий навчальний сценарій, який використовує загальну модель тестів, запитань, призначень і спроб.

## Розділення понять

- **Предмет** — математика, українська мова, англійська, природничий напрям або предмет учителя.
- **Клас/група** — навчальна група, де навчаються учні. Номер класу задається зв'язком предмета з групою, а не глобально для тесту.
- **Шаблон тесту** — назва, предмет, клас, тип оцінювання та налаштування.
- **Запитання** — незалежний тип (числове, коротка відповідь, один варіант, кілька варіантів); представлення запитання — JSONB для майбутніх медіа й спеціальних форматів.
- **Ключ відповіді** — приватні серверні дані, недоступні браузеру до перевірки.
- **Призначення** — зв'язує опублікований тест із конкретним класом і часовими умовами.
- **Спроба та відповіді** — фіксують виконання конкретним учнем; бал обчислюється сервером.

## Модель даних

Існуючі `schools`, `classes`, `profiles`, `class_teachers` і `class_students` задають межі доступу. До них додаються `subjects`, `class_subjects`, `assessment_templates`, `assessment_questions`, `assessment_assignments`, `assessment_attempts` і `assessment_responses`. Правильні відповіді зберігаються у схемі `private` окремо від таблиць, які читає клієнт.

## Розширення без зміни ядра

1. Новий предмет — рядок каталогу `subjects`.
2. Новий клас — значення `grade_level` у зв'язку `class_subjects`.
3. Новий тип питання — новий типізований рендерер/перевіряльник; існуючі записи залишаються валідними.
4. Нові режими (домашня робота, тренування, контрольна, банк запитань) додаються до шаблону/призначення, не створюючи окрему таблицю спроб для кожного предмета.
5. Предметні адаптери, як-от тренажер множення з п'ятьма рівнями, налаштовують загальний тест через дані й політики.

## План безпеки

- Усі таблиці в `public` мають RLS.
- Учитель читає й змінює лише свої шаблони та призначення для класів під його керуванням.
- Учень бачить опубліковане призначення для свого класу й власні спроби.
- Прямі INSERT/UPDATE у спроби й відповіді вимкнені для браузерного клієнта; їх відкриють через серверні функції після перевірки власника, термінів і ключа відповіді.
- Таблиця ключів відповідей залишається у `private`; її не додають до публічних grants.
- RLS для таблиць застосовується під час міграції; жоден тест не вважається опублікованим, поки стан шаблону `published` не виставлений учителем.
- Опублікований шаблон і його питання незмінні; правки оформлюються новою версією. RPC реєстрації вчителя закрито для браузерних ролей до появи перевіреного provisioning flow.

## Етапи

1. **Основа платформи:** каталог предметів, клас-предмет, шаблони, питання, призначення й спроби; RLS і приватні ключі відповідей.
2. **Учительський сценарій:** авторизація, класи й учні, редактор тесту, чернетки та публікація.
3. **Учнівський сценарій:** входження учня, список призначень, проходження, серверна перевірка й особиста історія.
4. **Множення:** перший конфігурований предметний тренажер із п'ятьма початковими рівнями.
5. **Розширення:** банк запитань, імпорт/експорт, зображення й аудіо, аналітика, інші типи тестів.

## Невирішені перед production

- Тарифи та пауза Supabase Free і сумісність GitHub Pages з авторизацією потрібно перевірити перед обіцянкою цілодобової доступності.
- Потрібні перевірені Edge Functions для provisioning учнів, видачі тесту, відповіді й підрахунку результату.
- Локальна чернетка зараз зберігається тільки у браузері; це явно показано в інтерфейсі.
